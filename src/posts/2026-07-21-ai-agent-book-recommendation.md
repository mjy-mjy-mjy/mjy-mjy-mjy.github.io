Agent 学习资料并不少，但真正能够同时覆盖系统原理、工程取舍和配套实验的中文资料并不多。

如果你已经理解了大模型调用、Function Calling 和基本 Agent Loop，希望进一步补齐上下文工程、RAG、工具系统、评估、安全、成本和多 Agent 等知识，可以关注李博杰开源的 **AI Agent Book**。

- 项目名称：《深入理解 AI Agent：设计原理与工程实践》
- GitHub 仓库：[bojieli/ai-agent-book](https://github.com/bojieli/ai-agent-book)
- 官方学习建议：[docs/LEARNING.md](https://github.com/bojieli/ai-agent-book/blob/main/docs/LEARNING.md)

这不是一本只讲概念的电子书。项目同时提供 Markdown 正文、电子书和按章节组织的实验代码，适合把系统阅读与机制验证结合起来。

## 一、这本书覆盖哪些内容

AI Agent Book 使用“模型、上下文和工具”作为理解 Agent 的核心框架，并扩展成 10 个章节。

| 章节 | 主题 | 主要内容 |
| --- | --- | --- |
| 第 1 章 | Agent 基础 | Agent 三要素、模型即 Agent、Harness 工程 |
| 第 2 章 | 上下文工程 | System Prompt、KV Cache、Skill、上下文压缩与安全 |
| 第 3 章 | 用户记忆与知识库 | Memory、RAG、混合检索、Rerank、知识图谱 |
| 第 4 章 | 工具系统 | MCP、工具分类、异步 Agent、主动工具发现 |
| 第 5 章 | Coding Agent | Coding Agent 架构、代码工具与工程机制 |
| 第 6 章 | Agent 评估 | 评估环境、指标、统计显著性、基准与模型选型 |
| 第 7 章 | 模型后训练 | 预训练、SFT、强化学习、工具调用内化 |
| 第 8 章 | Agent 自我进化 | 经验学习、工作流沉淀、工具创造 |
| 第 9 章 | 多模态与实时交互 | 语音、GUI、Computer Use、机器人 |
| 第 10 章 | 多 Agent 协作 | 分工、通信、隔离、协作框架与群体行为 |

项目还提供了大量配套实验。根据仓库说明，其中大部分实验可以独立运行，另一些属于外部项目复现、架构设计或读者练习。

因此，在运行前要先区分实验类型，而不是默认每个目录都包含完整的一键启动项目。

## 二、为什么值得推荐

### 1. 覆盖范围比单一 Agent 教程更完整

许多 Agent 教程会重点讲某一条主线，例如：

- 怎样实现工具调用；
- 怎样开发 Coding Agent；
- 怎样使用 LangGraph；
- 怎样搭建一个 RAG Demo。

AI Agent Book 的优势是把这些主题放进一套更完整的系统中。

它不仅讲 Agent 怎样运行，还讨论：

- 上下文预算与压缩；
- 用户记忆和知识库；
- 动态工具发现；
- MCP；
- Agent 评估；
- 提示注入与安全；
- Token、延迟和成本；
- 后训练与工具使用能力；
- 多模态交互；
- 多 Agent 竞态、通信与终止。

对于希望建立完整 Agent 工程认知的人，这种横向覆盖非常有价值。

### 2. 很多结论可以通过实验观察

这本书不是只告诉读者“应该怎样做”，而是提供了不少可以比较和验证的实验主题，例如：

- 不同上下文压缩策略的质量和成本差异；
- Prompt Injection 的攻击路径与防御效果；
- 稠密、稀疏、混合检索和 Rerank 的差异；
- 传统 RAG 与 Agentic RAG 的适用边界；
- 工具数量增加后对上下文和选择准确率的影响；
- 动态工具发现是否值得引入；
- 模型、Token、延迟与任务成功率之间的权衡；
- 多 Agent 并行中的竞态、重复执行和终止问题。

这类实验能够把“记住一个结论”变成“知道这个结论在什么条件下成立”。

### 3. 单独重视 Agent 评估

Agent Eval 是许多入门项目最容易忽略的部分。

一个 Demo 偶尔成功，并不能说明系统可靠。真正的 Agent 改进需要：

- 固定任务集；
- 明确成功标准；
- 可重复运行；
- 质量指标；
- Token、延迟和成本记录；
- 失败类型统计；
- 回归测试；
- 必要时进行统计显著性分析。

AI Agent Book 把评估作为独立章节，有助于建立一个非常重要的工程习惯：**任何策略改动，都应该通过稳定的评估集验证。**

### 4. 适合长期按问题查阅

这套资料既可以顺序阅读，也适合在做项目时按主题查找。

例如：

- 上下文太长时，查上下文压缩；
- RAG 效果不稳定时，查混合检索和 Rerank；
- 工具很多时，查动态工具发现；
- 系统费用升高时，查成本分析；
- 多 Agent 重复执行时，查幂等、终止与协作机制。

相比一次性的视频或零散文章，它更适合作为长期参考书。

## 三、哪些章节最值得优先学习

不建议从第一章开始平均用力地刷完全部章节和实验。

### 第一优先级：Agent 应用工程主干

建议优先学习：

- 第 1 章：建立 Agent 系统统一认知；
- 第 2 章：掌握上下文组成、压缩、缓存和安全；
- 第 3 章：学习记忆、检索、Rerank 与 Agentic RAG；
- 第 4 章：学习工具设计、MCP、异步执行和主动发现；
- 第 6 章：建立评估集、指标、回归测试和成本意识。

这五章与应用型 Agent 工程最直接相关。

### 第二优先级：按项目方向扩展

- 第 5 章：Coding Agent 与代码工具；
- 第 8 章：经验学习、工作流沉淀和工具创造；
- 第 10 章：多 Agent 的分工、通信、隔离与失败模式。

### 可以暂缓的部分

- 第 7 章：模型后训练；
- 第 9 章：实时语音、GUI、机器人和具身智能。

这些主题并不次要，只是学习成本更高，也不是构建常见 Agent 应用的最短路径。掌握单 Agent、RAG、工具和评估后，再根据职业方向深入会更合理。

## 四、值得优先尝试的实验

如果不打算运行全部实验，可以先选择下面几类。

| 实验方向 | 学习目标 | 建议记录 |
| --- | --- | --- |
| 上下文压缩 | 比较压缩策略 | 质量、Token、延迟 |
| Prompt Injection | 理解攻击与分层防御 | 攻击用例、成功率、绕过方式 |
| 检索流水线 | 比较检索、融合与重排 | Recall、NDCG、失败查询 |
| Agentic RAG | 对比传统 RAG | 质量、成本、延迟、失败案例 |
| 动态工具发现 | 观察工具规模影响 | 选择准确率、上下文开销 |
| Agent 成本分析 | 建立成本意识 | 单任务成本、成功率、耗时 |

运行实验时，不要满足于“成功启动”。

更好的方式是：

1. 在运行前写下预期结果；
2. 保存基线输入、输出和配置；
3. 每次只修改一个主要变量；
4. 记录质量、Token、延迟和成本；
5. 收集失败案例；
6. 分析结论在什么条件下不成立。

## 五、需要注意的局限

### 1. 实验代码不等于生产系统

教学实验能够验证机制，但生产系统还需要处理：

- 真实数据质量；
- 并发和持久状态；
- 身份认证与授权；
- API Key 和密钥隔离；
- 限流、幂等与重试；
- 任务恢复；
- 多租户隔离；
- 日志、Trace 和指标；
- 成本上限；
- 可复现部署。

因此，仓库代码更适合作为实验起点，而不是直接上线的模板。

### 2. 部分实验依赖受控环境

模拟数据、进程内消息总线、小规模样本和固定工具返回，很适合教学，却不能证明同样的架构在开放网络、真实用户和分布式环境中仍然稳定。

### 3. 内容很多，容易偏离主线

十章正文和大量实验看起来都值得学习，但同时展开会迅速分散精力。

更好的策略是根据自己的能力缺口选择章节，并把实验结果迁移到一个持续迭代的独立项目。

### 4. 快速更新意味着需要记录版本

Agent 技术仍在快速变化。模型 API、框架能力、工具协议和最佳实践可能更新。

涉及具体模型行为、性能数字和 API 能力时，应该回到官方文档、源码版本和原始论文复核。

## 六、怎样把它学成工程能力

可以为每个主题保留统一实验记录：

```text
目标：
假设：
实验环境与版本：
基线配置：
改动变量：
质量指标：
成本与延迟：
失败案例：
结论与适用边界：
下一步：
```

完成一轮学习后，不要只留下读书笔记，而应尝试形成一个真实项目。

例如，可以实现一个“个人 Agent 学习助手”：

- 从教材、学习笔记和 GitHub 文档建立知识库；
- 支持稠密与稀疏检索、融合、Rerank 和来源引用；
- 通过工具读取仓库、执行受限代码或更新学习进度；
- 带权限、错误恢复和上下文压缩；
- 使用固定问题集进行回归评估；
- 记录成功率、检索指标、Token、延迟和成本；
- 提供 Trace、日志、测试和可复现部署说明。

这样的项目能够把书中的 RAG、工具、评估和安全知识真正串联起来。

## 七、它适合哪些人

AI Agent Book 比较适合：

- 已经掌握 Python 和基本大模型 API 的开发者；
- 想从 Agent Demo 走向系统工程的人；
- 想系统学习 RAG、工具、MCP 和 Agent Eval 的人；
- 想了解 Coding Agent、多模态或多 Agent 全景的人；
- 需要一套中文 Agent 长期参考资料的人。

完全没有大模型和编程基础的读者，可能会觉得内容跨度较大。可以先从最小 Agent Loop 和工具调用入门，再选择性阅读本书。

## 八、我的推荐结论

AI Agent Book 是目前值得收藏的一套中文 Agent 系统教材。

它最突出的价值有三个：

1. **覆盖广**：从基础循环扩展到 RAG、工具、评估、安全、后训练、多模态和多 Agent；
2. **实验多**：能够通过对照和消融观察不同机制的效果；
3. **工程意识强**：持续关注上下文、成本、失败、评估和系统取舍。

但不建议把目标设为“读完十章、运行全部实验”。更有价值的完成标准是：

- 能解释模型、上下文、工具和 Harness 的关系；
- 能搭建并评估一条完整 RAG 流程；
- 能设计工具 Schema、权限和错误处理；
- 能接入 MCP；
- 能建立固定评估集和回归测试；
- 能同时记录质量、Token、延迟和成本；
- 能构造 Prompt Injection 测试；
- 能识别多 Agent 的竞态、终止和幂等问题；
- 能清楚说明实验走向生产系统还缺什么。

把这些能力沉淀进一个真实项目后，这本书才会真正从“值得收藏的资料”变成可复用的工程能力。
