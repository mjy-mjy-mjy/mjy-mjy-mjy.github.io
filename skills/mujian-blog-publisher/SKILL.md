# 沐简博客发布 Skill

## 目标

把一次性的博客写作协作，变成可以重复调用、持续改进并可验证的生产流程。

仓库：`mjy-mjy-mjy/mjy-mjy-mjy.github.io`

文章目录：`src/posts/`

文章资源目录：`src/assets/images/posts/<article-slug>/`

## 调用条件

当用户提出以下意图时使用本 Skill：

- 推荐博客选题；
- 编写或修改“沐简的博客”文章；
- 为文章制作插图、信息图或预览页；
- 将已确认文章提交到博客仓库；
- 复盘一次文章生产过程并更新长期规范。

每次执行前先读取：

1. `references/blog-profile.md`
2. `references/writing-style.md`
3. `references/visual-style.md`
4. `references/publishing-rules.md`
5. `references/lessons-learned.md`

需要具体格式时再读取 `templates/`；发布前使用 `scripts/` 中的校验脚本或执行等价检查。

## 运行模式

根据用户指令选择最小必要模式，不要擅自扩大写入范围。

### 1. 选题模式

适用指令示例：

> 调用沐简博客发布流程，给我推荐今天的选题。

执行：

1. 读取仓库现有文章标题、日期、标签与主题分布；
2. 找出内容缺口、可延续系列和近期值得讨论的技术话题；
3. 给出 3 个差异明显的候选题；
4. 每个候选题包含核心观点、切入场景和与旧文章的关系；
5. 推荐其中 1 个，但不创建文件、不修改仓库。

### 2. 初稿模式

适用指令示例：

> 调用沐简博客发布流程，以“……”为主题写初稿。

执行：

1. 读取相邻主题文章，避免重复；
2. 明确目标读者、核心观点与真实切入场景；
3. 对会变化、专业或容易记错的信息进行联网核验；
4. 生成完整 Markdown 初稿；
5. 不创建分支，不提交 GitHub。

### 3. 预览模式

适用指令示例：

> 调用沐简博客发布流程，把这篇文章做成可预览版本，不要提交。

执行：

1. 完成内容编辑与结构优化；
2. 判断文章是否真的需要配图；
3. 优先使用：氛围插图、精确 SVG 信息图、原生 HTML/CSS 卡片；
4. 生成独立单文件 HTML 预览页；
5. 同时提供独立图片素材；
6. 明确说明预览页与正式博客外壳可能存在的差异；
7. 不修改 GitHub。

### 4. 发布模式

适用指令示例：

> 预览没问题，调用沐简博客发布流程提交到博客，创建 PR。

执行：

1. 确认当前默认分支与最新仓库状态；
2. 从默认分支创建新的功能分支；
3. 写入 Markdown 和文章专属资源目录；
4. 只添加当前文章确实需要的通用样式；
5. 校验文章 Front Matter、链接、资源路径和重复 permalink；
6. 创建 Pull Request；
7. 等待 GitHub Actions 执行 `npm test`；
8. 汇报 PR 地址、改动范围和 CI 结果；
9. 未经用户明确要求，不合并 PR。

### 5. 完整模式

适用指令示例：

> 调用沐简博客发布完整流程，主题是“……”。

按以下阶段执行：

`选题与角度 → 调研 → 初稿 → 配图与独立预览 → 用户反馈 → 发布 PR → CI 验证`

默认人工确认点：

- 主题或核心观点存在明显歧义时；
- 预览方案完成后、写入仓库前；
- 合并 Pull Request 前。

用户已明确要求直接发布时，可以跳过预览确认，但仍不得跳过构建验证。

### 6. 改进模式

适用指令示例：

> 把这次反馈沉淀到沐简博客发布流程。

执行：

1. 区分单篇临时要求和长期偏好；
2. 只把可复用规则写入 `references/`；
3. 把一次任务中的有效做法与失败教训写入 `lessons-learned.md`；
4. 更新 `CHANGELOG.md` 和版本号；
5. 使用独立分支和 PR 交付 Skill 修改。

## 内容流程

### 读取现状

至少检查：

- 现有文章列表；
- 同主题文章；
- 最近文章的语气和结构；
- 当前布局、CSS 与静态资源规则；
- 未合并 PR，避免重复或冲突工作。

### 写作

文章必须具备：

- 一个清楚且可辩护的核心观点；
- 一个具体场景或实际问题作为切入口；
- 解释概念时与真实任务建立联系；
- 对关键结论给出原因，不停留在定义复述；
- 结尾回到读者可以使用的判断框架。

### 配图

只有当图能完成以下至少一项任务时才添加：

- 建立阅读氛围；
- 解释文字难以快速说明的关系；
- 打断长篇文字并改善阅读节奏；
- 展示界面、结构或执行过程。

不得为了“看起来丰富”而机械增加图片。

### 验收

不能把以下情况称为完成：

- 只生成了文章文本；
- 只修改了仓库文件但没有检查构建；
- 图片存在但路径未验证；
- PR 已创建但 CI 失败或尚未确认结果；
- 预览页与正式实现差异没有说明。

## 输出约定

每次发布完成后汇报：

- 文章标题与 permalink；
- 分支名与 PR 地址；
- 新增/修改文件摘要；
- 图片资源目录；
- 构建与站点检查结果；
- 是否已合并、线上是否已更新。

## 安全边界

- 不直接向默认分支提交；
- 不在用户未明确要求时合并 PR；
- 不删除旧文章或公共样式，除非任务明确要求且已检查影响范围；
- 不把生成式图片中的中文当作精确正文信息；
- 不伪造调研来源、构建结果或线上状态；
- 不把临时文章要求自动升级为永久风格规范。
